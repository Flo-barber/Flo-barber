Mise en route
comptes & clés d'API

Les cinq services à provisionner pour passer le site en production, dans l'ordre. Pour chacun : le compte à créer, où récupérer chaque clé, et ce qu'il faut activer côté service. Chaque clé indique la variable du .env.local qu'elle remplit.

⚑ Avant de créer quoi que ce soit — propriété des comptes

Pour une livraison propre, crée chaque compte au nom du client (email pro du client, société + IBAN pour Stripe), puis fais-toi inviter comme membre/développeur. Sinon, c'est toi qui restes titulaire des accès et de la facturation, et le transfert après coup est pénible (surtout Stripe, lié à une entité légale).

Utilise idéalement une adresse partagée type contact@flobarber.fr comme compte propriétaire, et garde les secrets hors du dépôt : .env.local et la clé de service Google sont déjà gitignorés.

À demander au client

Les informations à réunir avant d'ouvrir les comptes. Tant que la partie « Société & légal » n'est pas fournie, Stripe ne peut pas être activé en paiement réel et les mentions légales / CGV restent incomplètes. Les services, dans l'ordre

À faire en premier — compte Google dédié

Prérequis · avant tous les autres comptes

Créer un compte Google (Gmail) gratuit dédié au projet (ex. contact.flobarber@gmail.com). Il joue deux rôles : il sert de compte Google pour Google Cloud + la Wallet Console (§03), et de mail de référence / propriétaire pour tous les autres comptes (GitHub, Supabase, Stripe, Cloudflare, Vercel).

  • Choisir une adresse générique (pas un prénom) pour qu'elle reste liée au projet.
  • Mot de passe fort + 2FA activée, et conserver les codes de secours — cette adresse commande tous les comptes.
  • Ouvrir ensuite chaque service ci-dessous avec cette même adresse.
Nom de domaine = étape future. Pas besoin du domaine du client pour démarrer : on travaille d'abord sur une URL de test …vercel.app avec ce Gmail. Le mail pro @domaine et le branchement du domaine se feront plus tard, sans rien casser.
00

GitHub

Héberge le code source. C'est le prérequis dont dépend Vercel : c'est ce dépôt qui est déployé.

Gratuit github.com
Créer le compte et le dépôt
  1. Aller sur github.com → Sign up ; créer le compte avec le Gmail dédié (voir « À faire en premier »). Valider l'email de vérification.
  2. (Recommandé) Créer une organisation au nom du client : en haut à droite, ton avatar → Your organizations → New organization → plan Free → nom ex. flo-barber. Ça garde le code « propriété du client ».
  3. Créer le dépôt : bouton New (ou + → New repository) → Repository name : Flo_barber → visibilité Private → ne pas cocher « Add a README » (le code existe déjà) → Create repository.
Pousser le code + t'ajouter
  1. T'ajouter comme accès : dépôt → Settings → Collaborators (ou, pour une orga, People → Invite member) → inviter ton compte perso → rôle Write (ou Admin).
  2. Envoyer le code existant depuis ton Mac (Terminal) :
    cd ~/www/Flo_barber
    git remote set-url origin https://github.com/<compte-ou-orga>/Flo_barber.git
    git push -u origin main
  3. Alternative au push : transférer l'existant SleepFast/Flo_barber → dépôt actuel → Settings → Danger Zone → Transfer ownership vers le compte du client (conserve historique, issues, réglages).
  4. Vérifier que .gitignore couvre bien .env.local et flo-barber-wallet-*.json (déjà le cas) — ne jamais commiter ces fichiers.
C'est ce dépôt que Vercel déploiera (§05), automatiquement à chaque git push. Créer le dépôt directement sous le compte du client évite un transfert plus tard.
01

Supabase

Base de données, authentification et cœur du programme de fidélité.

Pro conseillé supabase.com
Créer le projet
  1. supabase.com → Start your project → se connecter avec le Gmail dédié (ou le GitHub du client).
  2. New organization au nom du client, puis New project.
  3. Renseigner : Name = Flo Barber ; Database Password = générer et noter dans le gestionnaire ; Region = West EU (Paris) ou Central EU (Frankfurt) → Create new project (attendre ~2 min le provisionnement).
  4. Plan : Free pour développer ; pour la prod, Settings → Billing → passer en Pro (~25 $/mois) — sinon pause après ~1 semaine d'inactivité et pas de sauvegardes quotidiennes.
Où récupérer les clés · Settings → API Keys
Project URL (Settings → API, ou bouton Connect en haut)NEXT_PUBLIC_SUPABASE_URL
Clé anon (section « Legacy / JWT », format eyJ…)NEXT_PUBLIC_SUPABASE_ANON_KEY
Clé service_role (Legacy, eyJ…) secret serveurSUPABASE_SERVICE_ROLE_KEY
Bien prendre les clés « legacy » (anon et service_role, format JWT eyJ…) : c'est ce que le code attend. Les nouvelles clés sb_publishable_… / sb_secret_… coexistent dans le même écran mais ne sont pas utilisées ici.
Configurer la base
  1. SQL Editor → New query → coller tout le contenu de supabase/schema.sql → Run (crée tables, RLS, triggers, fonctions de points).
  2. Storage → New bucket → nom products (minuscule) → activer Public bucket → créer (la lecture publique des images est ainsi assurée).
  3. Policies d'écriture du bucket : SQL Editor → exécuter supabase/storage-policies.sql (écritures réservées aux admins). ⚠️ Ces policies Storage ne sont pas dans schema.sql — étape à part.
  4. Authentication → Providers → activer Email. Puis Authentication → URL Configuration → renseigner Site URL + Redirect URLs : http://localhost:3000 (dev) et l'URL Vercel/domaine (prod).
  5. Créer un admin : s'inscrire via le site (ou Authentication → Users → Add user), puis Table Editor → table admins → insérer une ligne avec l'id de ce compte.
  6. Captcha (après §04) : Authentication → Settings → Attack Protection → Enable Captcha protection → provider Turnstile → coller la Secret key Turnstile → Save.
02

Stripe

Paiement de la boutique (Checkout hébergé) + crédit des points via webhook.

Sans abonnement stripe.com
Créer le compte
  1. stripe.com → Sign up (email = Gmail dédié), pays = France.
  2. Rester en Test mode (interrupteur en haut à droite) pour tout le développement — pas besoin des infos société à ce stade.
  3. Activer les paiements réels plus tard : Activate account (bandeau du dashboard) → remplir entreprise (SIRET), représentant légal, IBAN. Pas d'abonnement — commission par transaction.
Récupérer la clé · Developers → API keys
Secret key (Standard keys → Reveal, sk_test_… puis sk_live_…) secretSTRIPE_SECRET_KEY

La clé « publishable » n'est pas utilisée (Checkout hébergé).

Configurer le webhook
  1. Developers → Webhooks → Add endpoint → Endpoint URL : https://<url-vercel-ou-domaine>/api/webhooks/stripe.
  2. Select events → cocher checkout.session.completed et checkout.session.expired → Add endpoint.
  3. Ouvrir l'endpoint créé → Signing secret → Reveal → copier (whsec_…) → STRIPE_WEBHOOK_SECRET.
Piège connu : sans l'event checkout.session.expired, les points « réservés » à un panier abandonné ne sont jamais libérés (session à expiration courte, 30 min). À cocher impérativement.
En local : installer la Stripe CLI, stripe login, puis stripe listen --forward-to localhost:3000/api/webhooks/stripe → fournit un whsec_ de test à mettre dans .env.local le temps du dev.

03

Google Cloud + Wallet

Carte de fidélité ajoutable à Google Wallet. Deux consoles à provisionner.

Gratuit console.cloud.google.com · pay.google.com/business/console
A · Google Cloud Console — console.cloud.google.com (Gmail dédié)
  1. En haut, sélecteur de projet → New project (ex. « flo-barber-wallet ») → Create.
  2. APIs & Services → Library → chercher « Google Wallet API » → Enable.
  3. IAM & Admin → Service Accounts → Create service account → nom ex. wallet → Done. Noter l'email du compte de service (…@….iam.gserviceaccount.com).
  4. Ouvrir ce compte → onglet Keys → Add key → Create new key → JSON → le fichier se télécharge.
  5. Encoder en base64 sur ton Mac : base64 -i flo-barber-wallet.json | pbcopy → colle dans GOOGLE_WALLET_SERVICE_ACCOUNT. Garder le .json hors du dépôt.
B · Google Pay & Wallet Console — pay.google.com/business/console (même Gmail)
  1. Créer le compte émetteur : renseigner le nom public de l'entreprise + accepter les CGU Google Wallet.
  2. Sur la page Google Wallet API, relever l'Issuer ID (numéro affiché en haut) → GOOGLE_WALLET_ISSUER_ID.
  3. Users → Invite a user → coller l'email du compte de service (étape A) → rôle Developer → confirmer. C'est ce qui l'autorise à créer les cartes.
  4. Page Google Wallet API → Request publishing access (sinon l'émetteur reste en mode démo).
Récapitulatif des clés
Issuer ID (Wallet Console)GOOGLE_WALLET_ISSUER_ID
JSON du compte de service, encodé base64 secretGOOGLE_WALLET_SERVICE_ACCOUNT
Logo PNG public (optionnel)GOOGLE_WALLET_LOGO_URL
Suffixe de classe (optionnel)GOOGLE_WALLET_CLASS_SUFFIX
Mode démo : tant que l'accès de publication n'est pas accordé, l'émetteur reste en démo — bandeau « démo » sur la carte et ajout limité aux comptes de test. Le logo doit être un PNG public (pas de SVG, pas de localhost).
04

Cloudflare Turnstile

Captcha anti-bot sur l'inscription et la connexion.

Gratuit cloudflare.com · Turnstile
Créer le widget
  1. Créer un compte sur dash.cloudflare.com (Gmail dédié), puis menu de gauche → Turnstile.
  2. Add widget → Widget name ex. « Flo Barber ».
  3. Hostnames : ajouter localhost (dev) et l'URL/domaine de prod ; Widget mode : Managed (recommandé) → Create.
  4. La page affiche alors la Site key et la Secret key — les copier.
Où vont les clés
Site key (publique)NEXT_PUBLIC_TURNSTILE_SITE_KEY
Secret key → dans Supabase, pas dans le .envSupabase → Auth → Captcha
Bon à savoir : si NEXT_PUBLIC_TURNSTILE_SITE_KEY est vide, le captcha est simplement désactivé — pratique en dev, à renseigner avant la mise en ligne.
05

Vercel

Hébergement de l'app Next.js (HTTPS auto, requis pour la caméra du scanner).

Pro vercel.com
Créer le compte et importer
  1. vercel.com → Sign up → Continue with GitHub (connecter le compte GitHub du client, §00).
  2. Plan : Hobby gratuit mais interdit en usage commercial → prendre Pro (~20 $/siège/mois) pour un site client.
  3. Add New → Project → importer le dépôt Flo_barber (autoriser Vercel à y accéder si demandé). Next.js est détecté automatiquement.
Variables d'environnement + déploiement
  1. Avant de déployer, section Environment Variables → recopier chaque ligne du .env.local (Name / Value).
  2. Mettre NEXT_PUBLIC_SITE_URL = l'URL Vercel (…vercel.app) tant qu'il n'y a pas de domaine — sert aux retours Stripe.
  3. Deploy → attendre le build → l'app est en ligne sur l'URL …vercel.app (HTTPS auto, requis pour la caméra du scanner).
Domaine — étape future
  • Settings → Domains → ajouter le domaine du client et suivre les enregistrements DNS indiqués (certificat HTTPS automatique).
À chaque changement d'URL/de variable : reporter l'URL de prod dans le webhook Stripe (§02) et les Redirect URLs Supabase (§01), puis relancer un déploiement pour que les variables soient prises en compte.

Toutes les variables listées ici correspondent aux repères => À COLLER déjà présents dans .env.local. Les coûts (Supabase Pro, Vercel Pro) sont indicatifs — à confirmer sur les pages tarifaires au moment de la souscription. Ne jamais commiter .env.local ni la clé de service Google.
